kind: **ADDED**: `spawn adapter` checks each group's egress list against `egress-approved.toml`
---
`spawn adapter --check` now reads `egress-approved.toml` beside the config file and prints each group's effective egress list; `spawn adapter` refuses to start when a group's `egress` entry is not approved for every repo of that group (`command::load_egress`). A missing file counts as empty, so a config with no extras needs none. 1 test with a known-bad control (the same entry refused with no file, accepted once approved, a malformed file named in the error). Listener probes wait for the pool switches (ROADMAP row 39).

Also `adapter::vm_backend` (ROADMAP row 40, not wired to any group): `VmBackend` runs one runner per Hyper-V VM (a differencing child of the read-only base, one NIC on a pool switch, no checkpoints), verifies the base hash once and destroys the VM on every exit path, with a `VmHost` seam and `ScriptHost` building the PowerShell as quoted, prefix-checked text; 12 tests. The guest channel (JIT delivery, runner-end wait) is not built.

And `spawn-egress --check-sni`: the proxy reads the first TLS record and refuses a tunnel whose SNI is not the `CONNECT` host (domain fronting through an allowed name); a parser that never indexes past its buffer, 3 tests, measured live on loopback.

Guest credential (ROADMAP row 40; CireSnave board 488, "A"): `scripts/store-guest-credential.ps1` stores the baked image's one Administrator password as a DPAPI user-scope file (`%LOCALAPPDATA%\antspawn\guest-credential.dpapi`) from a hidden prompt; dry run by default, `-Apply`, `-Undo`. `adapter::guest_credential` checks the file decrypts (never reporting any of it), and `spawn adapter --check` exits 2 with a plain message when a `hyperv-vm` group has no readable file. `ScriptHost::wait_end` now polls the guest over PowerShell Direct, building the `PSCredential` from the file inside the PowerShell process (the password is never in script text, an argument, a log or a result). 5 + 1 tests (file not plaintext, check says none of it, plaintext/empty files fail, preamble holds no password). `examples/vm_pilot.rs` runs it on a real VM (measured 2026-11-22, this laptop, one run after the fixes): base hash verify 50 s, create 9 s, start 2 s, guest answering PowerShell Direct 12 s after start, `hostname` in the guest 6 s, the runner-end wait timing out as it must with no runner, destroy 2 s, nothing left behind. Two defects the run found and this fixes: `hyperv::PowerShell` now passes the script with `-EncodedCommand` (a multi-line script on stdin to `-Command -` ended at once with exit 0 and no output, so a readiness wait returned in 0.6 s having done nothing), and `wait_ready` now waits for PowerShell Direct to answer, not only the heartbeat (the first session sent right after the heartbeat broke after 30 s). Not yet done: the JIT delivery transport, and the runner-end wait with a runner actually present.
