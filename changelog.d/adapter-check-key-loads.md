kind: **ADDED**: `spawn adapter --check` now loads the App key
---
`--check` only looked at the key path. It now also loads the key through the configured provider (DPAPI as the current user by default, `--pem-key` for a plain PEM) and checks it is a PEM private key, printing only the length (`command::check_with_key`, `key_loads`). A run as another account, or a wrong `--pem-key`, now fails at `--check` instead of at start. Measured 2026-11-21 on this box with the real App key at `%LOCALAPPDATA%\antspawn\github-app` (path from the PM, who ran `github-app-setup.ps1 -Verify`): `--check` prints `key: loads, 1674 bytes, PEM private-key header present`, exit 0; control, the same file with `--pem-key`: `key: loads but is not a PEM private key`, exit 1. Offline: nothing is sent to GitHub; the key never leaves the process or any output. Not measured: a load as a different account; `spawn adapter run`/`--once` (ROADMAP row 23).
