kind: **ADDED**: `spawn adapter --check` now loads the App key
---
`--check` only looked at the key path. It now also loads the key through the configured provider (DPAPI as the current user by default, `--pem-key` for a plain PEM) and checks it is a PEM private key, printing only the length (`command::check_with_key`, `key_loads`). A run as another account, or a wrong `--pem-key`, now fails at `--check` instead of at start. Measured 2026-11-21 on this box with the real App key at `%LOCALAPPDATA%\antspawn\github-app` (path from the PM, who ran `github-app-setup.ps1 -Verify`): `--check` prints `key: loads, 1674 bytes, PEM private-key header present`, exit 0; control, the same file with `--pem-key`: `key: loads but is not a PEM private key`, exit 1. Offline: nothing is sent to GitHub; the key never leaves the process or any output. Not measured: a load as a different account; `spawn adapter run`/`--once` (ROADMAP row 23).

Also added: the egress proxy's decision core (`antspawn::egress`: CONNECT only, port 443 only, exact or `*.domain` host allowlist, loopback/private/link-local resolved addresses refused so an allowed name cannot reach the host, fail-closed on any malformed head, one-line deny log that a hostile request cannot forge; 12 tests, each rule with a known-bad control) and the per-group `egress = ["host:443"]` list with the `egress-approved.toml` loader (`adapter::egress_policy`: an entry is refused unless approved by name for every repo of the group; a wildcard needs `wildcard = true`; 6 tests). Neither is wired to a switch, a firewall rule or `spawn adapter --check` yet (ROADMAP rows 38, 43); also the Server Core pilot scripts and the measured offline install recipe (`docs/RUNNER-VM-PATH.md`: Build Tools, runner layer, vendor layer baked into a laptop-local read-only base).

And the unattended adapter (PM ruling A, ROADMAP row 36): `spawn adapter --status-file` writes a small status file after each tick and holds a lock so one adapter runs; `scripts/adapter-run.ps1` (check, start, record the exit code) and `scripts/adapter-task.ps1` (dry-run-first registration of a logon task for the current user, no stored password). The task is not registered.
