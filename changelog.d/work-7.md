ROADMAP row 40 per the PM ruling of 2026-11-26 (no long-lived guest credential). `VmBackend` now makes a fresh password per VM (`adapter::guest_secret::fresh`: 32 random bytes, `Aa1-` + hex), `VmHost::provision` hands it to the host PowerShell on stdin, which makes `%LOCALAPPDATA%\antspawn\guests` this-user-and-SYSTEM only (inheritance removed, ACL read back before any secret is written), stores it as a DPAPI CurrentUser blob in `<vm>.cred` there and puts it on the VM bus as a data-exchange item; PowerShell Direct reads that VM's blob, the item is removed once the guest answered, the blob is removed with the VM. `VmHostConfig.guest_credential` and `VmTransport.guest_credential` became `secret_dir`; `spawn adapter --check` now creates and checks that folder is writable, non-elevated (exit 2 on `guest secret:` problems). `scripts/guest-bootstrap.ps1` is the guest-side startup task. `script_create` keeps the Key-Value Pair Exchange service. Red-first tests: two builds give two different passwords; the password is on stdin and in no script text, error or bootstrap code (with known-bad controls); the item is sealed only after the guest answered; the blob goes with its VM after `Remove-VM`.
NOT measured: any of the Hyper-V data-exchange path, the bootstrap task, or a job over it. It needs a rebake of the base image (random unkept Administrator password, startup task) (the ACL step itself was run on a temp folder that started with an extra explicit ACE: it ended at this user and SYSTEM, blob not plaintext). The old fixed password remains only for the pilot/build tooling (`guest_credential`, `store-guest-credential.ps1`).

Also in this PR: Board 503 `-Apply` failed its own ACL read-back: `%ProgramData%\antspawn-pool` already existed with an explicit ACE for a user, and `icacls /inheritance:r /grant:r` replaces only the SIDs it names. The script now runs `icacls <dir> /reset` first, then drops inheritance and grants Administrators and SYSTEM, and keeps the read-back. Verified: the same icacls sequence on a temp folder with an extra explicit ACE left exactly Administrators and SYSTEM; `tests/broker_pool_script.rs` pins the order (reset, inheritance, read-back) with a known-bad control. The elevated `-Apply` itself is not re-run here.
